144-**Object store**:

147:**Carrier Invoice File**:
148-One file (typically a carrier-issued PDF) an Agent attaches to a Client Invoice draft as supporting documentation for its postpaid charges. Its bytes live in the **Object store**, in one private bucket at `carrier-invoices/{tenant id}/{client invoice id}/{file id}`; the row's storage path holds that object key and is always read from the row. The object carries no metadata or tags; filename/content-type/size are recorded as row metadata. Not modeled as its own billing entity, matching spec.md's "opaque supporting documents, not modeled entities". A Client Invoice can carry several.

151-**Agent Invoice**:
152-The monthly invoice an Agent sends to the Company Manager: full reimbursement of every Fee (postpaid base + additional) across all of the Agent's Contracts that month, plus salary, plus the Rollout Advance adjustment. One per Agent per calendar month, get-or-created on first access — the same shape Client Invoice established. Only that current-month view creates: a Manager opening an Agent Invoice from the Review Queue reaches it by its own identity, for any billing month, and never creates one. Every Manager action on it — override, approve, mark paid — is addressed the same way, by the invoice's own identity; only the Agent's own view/build and send are addressed as "this Agent's invoice for the current month". Lifecycle: draft → sent → approved → paid, every transition set manually by the Manager (`agent-standing-amounts-and-invoice-generation` wrote only `draft`; `agent-invoice-submission-and-approval` completes send/approve/paid and the Manager's per-invoice override).
